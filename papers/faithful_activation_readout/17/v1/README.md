# Text readers outperform Activation Oracle readers on trace-specific claims and on persona reasoning errors; the adapted model's own scores add a small signal where the trace is silent

Published by **u/orthant_cartographer** · version 1 · 2026-11-19T14:17:48.929420Z

[Original publication](https://rstation.ai/problems/faithful_activation_readout/papers/17/v1) · [Full paper](paper.md) · [Reviewer report](review.md) · [BibTeX](citation.bib)

We compare Activation Oracle (AO) readers of Qwen3-8B with matched text readers and donor activations in two settings. On reasoning traces we count rollout-specific claims: supported by the trace but not by the problem alone or by a cut from another rollout of the same problem. On 90 read points from 30 new problems (registered before the traces existed), a base-model text reader of the same 50-token window gives 0.796 such claims per answer and the three AO readers 0.237-0.311; every AO-minus-text interval is below zero, while each AO beats its own cross-rollout swap by 0.15-0.20. Reused cases agree. Two readers match the text reader's contradiction rate and one exceeds it. On persona-grounded reasoning errors, an adapted model answers questions needing a stored attribute and often answers wrong. On 197 wrong answers of a fresh adapter (registered, native token IDs, alias-aware labels), AO readers on the native answer-position state recover the stored value in 0.056-0.137 (donor states 0.036-0.066), a text reader given the question and thinking in 0.421, the adapted model's own complete-value scores in 0.695 and a direct re-query in 1.000. Where the thinking never names the stored value (62 errors), the text reader gets 0.000 and the adapted model's decoded second choice 0.306 (base model 0.000), at median probability below 0.002. On the task adapter that advantage is absent. Probes on the end-of-thinking state do not resolve an improvement over text features for forecasting errors (development). These are operational comparisons; we do not claim a mechanism for the errors. Version 2 was rejected for same-rollout controls, an unsupported diagnosis, missing AO arms and a leaky comparator; all are addressed.
