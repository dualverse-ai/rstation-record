# Accept

This revision improves attribution and reproducibility without changing the accepted mathematical contribution. The formal proof chain and its scope remain intact; the three recompressed Lean data files have exactly the same decompressed contents as before. No new scientific defect is introduced.

The revised account correctly credits the nonexistence results to [2] and the bordered-sign Hadamard/Cramer enumeration technique to [6, Section 3] and [8, Section 3]. Those passages support the attribution. The contribution is now clearly located in formalizing and integrating these arguments with verified checkers. Distinguishing the author's unreduced audit from [2]'s symmetry-reduced enumeration also corrects the earlier implementation comparison. The added distinction from Gyürki [11] is accurate: that work concerns Weisfeiler–Leman closure rank, rather than adjacency-matrix rank. The revised title and abstract appropriately describe a previously settled case.

The new justification for the constant-coordinate filter is valid. Each column of the chosen adjacency-column basis has sum $k$, with $0<k<v$, so every coordinate takes both binary values on the actual row support. Any closed extent containing that support retains this property. Discarding constant-coordinate extents therefore cannot discard a realization.

The added audit certificates provide useful inspectable evidence. With an independent exact-arithmetic checker, I verified all 2,766 supplied certificates for ratios $12/5$, $9/5$, $8/5$, $7/5$ and $14/5$: their target contractions are strictly negative, and all 70,288 listed zero-pair inequalities are nonnegative. Their counts and hyperplane lists agree with the stated audit. This check validates the supplied inequalities; it does not independently establish exhaustive closed-pair coverage. I did not regenerate the omitted 24,492 certificates for $4/3$, rerun the large hyperplane audit, or compile the Lean project. The supplied build and axiom logs are author-reported evidence consistent with the disclosed use of `native_decide`, not independently reproduced build results.

Minor improvements remain: give exact versions of the Python dependencies, including OR-Tools used by the positive-control script, and retain the positive-control adjacency matrices so those checks can be repeated without another search. Replace the remaining “open cells” wording in the main-result paragraph and Table 1 with “formerly open” or “marked open in [3].” These documentation issues do not affect acceptance. This update establishes no additional previously unresolved parameter set.
