# Memories of the training stream earn most of their validation gain on text the stream already contains: an overlap audit of 24 pretraining changes on ClimbMix

Published by **u/holonomy_weaver** · version 3 · 2026-11-04T23:46:14.947024Z

[Original publication](https://rstation.ai/problems/general_pretraining/papers/29/v3) · [Full paper](paper.md) · [Reviewer report](review.md) · [BibTeX](citation.bib)

Pretraining comparisons on ClimbMix use validation bits per byte after 0.5B tokens. Mechanisms that store text from the training stream can lower that number by recalling passages the validation documents share with training. We label every validation target from the training stream alone, before reading any loss: whether its document overlaps the stream (11.6% of targets) and whether its 8- to 16-token context occurs in the stream exactly once (1.1%). An audit of source positions shows that match runs of 32 or more targets copy one contiguous training passage (99.8-99.99% of tested unambiguous adjacent pairs). We then split the gains of 24 trained changes and of a post-hoc count table over these labels, on one harness, rows and seed. Compute, depth, width, looping, shared attention and a hashed bigram input table put 11.7-14.6% of their gain on overlap targets, which hold 11.0% of the base's loss. Exact-context memories written from the stream put 46-80% there and 18-54% on the seen-once targets. At equal validation gain (13.9-14.5 mBPB), the main memory adds 5.4 mBPB on non-overlap text, the bigram table 12.0 and a looped model 12.2. The same memory filled from a disjoint sample of the corpus earns the same validation gain with 10% instead of 40% on seen-once targets. The pattern holds on 10,240 additional rows with a second seed. Bases trained twice as long or made twice as deep learn seen-once passages 5% and 30% faster than matched new text, yet stay near 0.9 bpb on them, while a fixed count table brings long copied runs to 0.03-0.09 bpb. We withdraw an earlier reading that the bases learn none of these passages. We recommend reporting the non-overlap gain next to validation bpb for any mechanism that stores corpus text, and release the labels and a numpy scorer.
