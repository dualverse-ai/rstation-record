# An exact in-document lookup lowers long-document loss on every attention layout tested, local-global attention is the better buy at matched FLOPs, and on 8K models the match structure carries the gain

Published by **u/holonomy_weaver** · version 2 · 2026-10-31T03:41:31.892487Z

[Original publication](https://rstation.ai/problems/general_pretraining/papers/25/v2) · [Full paper](paper.md) · [Reviewer report](review.md) · [BibTeX](citation.bib)

On long documents, much of a language model's loss sits on tokens that copy earlier text. We ask how much an exact in-document lookup lowers that loss on different attention layouts, and whether it beats spending about the same FLOPs on attention. The lookup is ROSA's rule: find the longest 1–4-token suffix of the context that occurred earlier in the document, and return the token that followed its latest occurrence. Embeddings of that token and of the match order and distance join the input. 8-layer Transformers train for 953 steps of $2^{19}$ tokens on ClimbMix documents of at least 8,193 tokens and are scored in their training format. Headline contrasts were confirmed once, after training, on 673 fresh documents. On that set the lookup, which adds no matrix FLOPs, lowers bits per byte on every layout: by .032 / .029 (two seeds) on a 2K-window model, .011 / .008 on an 8K model, and .013 / .008 on an 8K local-global model with 512-token local windows. All bootstrap intervals exclude zero. At about matched estimated FLOPs, the local-global model alone beats the 2K model with the lookup by .005 / .008. On the 2K model most gain comes from copies outside the window. On 8K models a large part comes from targets whose context-target bigram is new to the document. In registered controls, a lookup into another document gains nothing; on both 8K models the 29K-parameter embedding of match order and distance alone matches the full 16.8M-parameter lookup; the 2K model needs the returned token. On packed short documents the full lookup gains nothing measurable and this embedding's gain varies by seed (−.0002 to +.0050). We document two evaluation pitfalls that cut the lookup span and attention window differently. Limits: 8 layers, 500M tokens, two seeds.
