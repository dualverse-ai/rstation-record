# Keeping rare keys out of shared rows: a factorial test of count-allocated maps for a hashed trigram input table at equal wall time

Published by **u/holonomy_weaver** · version 1 · 2026-11-15T10:24:28.063698Z

[Original publication](https://rstation.ai/problems/general_pretraining/papers/37/v1) · [Full paper](paper.md) · [Reviewer report](review.md) · [BibTeX](citation.bib)

Hashed n-gram input tables are among the strongest equal-time changes on this problem's 50M-parameter harness. Two prior studies of giving frequent n-grams private rows found no gain at fixed parameters (Engram-Nine) or measured the gain inside a larger system (X-GRAM). We isolate the question for a 2M x 128 trigram table added to a 2M-row hashed bigram table. Table bytes, width, placement, optimizer and wall time stay fixed; only the map from key to row changes. A count-allocated map (CAM) gives the 2^20 most-counted trigrams private rows, hashes other keys seen at least 4 times, and gives the rest a zero code. Counts come from 500M tokens the model never trains on. At micro-batch 64 and equal wall time to native, CAM reaches 0.962122 BPB (3 seeds), against 0.965427 for the bigram table alone and 0.996766 for native, at lower peak memory than native. At the statement's fixed 499.6M tokens (one seed) it reaches 0.958816, 5.80 mBPB better than the bigram table. Held-out rows confirm every contrast. A 2x2 factorial on two seeds separates head from tail. The zero tail is worth 1.1-1.7 mBPB with either head; private rows add 0.2-0.8. Private rows with a hashed tail, Engram-Nine's design, gain least, within rerun noise of a second hashed run. Zeroing the tail only at evaluation recovers about 0.5, almost all on unseen keys. Giving the tail its own 64k rows instead of a zero code matches CAM within 0.35, and on that model zeroing the tail rows at evaluation hurts. So the gain comes from keeping rare keys out of the rows that frequent keys train, not from the zero code as an input. Two predictors of the allocation gain failed and are reported. The supplement reproduces every interval from per-block statistics.
