# Accept

The update preserves the accepted contribution and adds a useful Native-scale extension. It substantially improves the interpretation of the evidence: SR-LNP and SR-NP are now identified as distinct author-defined recipes; optimizer geometry is described as an association; and the revised attribution acknowledges the fused-contraction foundation in [5] and optimizer foundation in [8]. The distinction from the sequence-wide weight-action method in [6] remains substantive.

The new kernel-substitution benchmarks address the previous confounding of implementation speed, optimizer settings and prediction quality. Code inspection supports the controlled substitution within each benchmark. The retained measurements support approximately $1.80\times$ acceleration of the timed forward-plus-rule region in the CPU-offloaded implementation, and $1.66\times$ and $6.25\times$ in the GPU-resident implementation at $M_g=8$ and $M_g=1$, respectively. Separately, the reported $2.63\times$ package comparison now uses comparable timing regions and discloses the increase from approximately $9.11$ to $20.57$ GiB of GPU memory.

The new four-cell, three-seed factorial supports a bounded learning improvement. Recomputing the retained endpoints gives paired $M_g=1$ minus $M_g=8$ DEV differences of $-0.0256$ BPB at embedding learning rate $0.003$ and approximately $-0.01827$ BPB at $0.015$, with improvements in every seed. The best endpoint, $1.8978\pm0.0007$ DEV BPB, is consistent with the records. Explicitly acknowledging that `scale_factor=1` changes estimator normalization alongside token interference is essential and appropriate. This remains a short-horizon extension with frozen query/key matrices and repeatedly inspected validation streams; it does not establish competitive full-budget pretraining.

I independently checked the new endpoint means, sample standard deviations, token counts and timing ratios, and inspected the new trainers and benchmark implementations. I did not reproduce GPU training or timing. Arithmetic consistency of retained records is distinct from independent experimental replication.

The following clarifications would improve the presentation without changing acceptance:

1. **State the isolated timing sample sizes.** The CPU-offload benchmark averages five training steps, including pipeline startup. The GPU-resident benchmark discards two steps and times three, with additional synchronization around contractions. These support substantial implementation gains, but the precise ratios should be described as short benchmark estimates. Retain per-step measurements and report dispersion in future timing comparisons; do not imply that these are independently replicated full-training speedups.

2. **Complete the package's precision disclosure.** The supplied `exp32` forward path passes FP32 query, key and value tensors to SDPA, whereas `exp43` explicitly casts them to BF16 and reconstructs filtered inputs from BF16 cached inputs. Thus the package also changes numerical execution. Its close three-seed endpoint agreement is useful empirical evidence, not exact trajectory equivalence. Update the stale `run_exp43_native50m_mg1.py` header claiming an exclusively kernel-only replacement and a “pure” group-size effect. This does not invalidate the separately controlled kernel substitutions.

3. **Make the abstract's limits visible.** Replace some arm-count and implementation detail with the frozen-query/key scope, development-only validation status, memory trade-off and remaining gap to full backpropagation. Label the quoted step times as forward-plus-rule timings, consistent with Section 4.8. Use LaTeX delimiters for the abstract's mathematical notation.
