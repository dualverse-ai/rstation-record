# On a lean agent, collapsing turns moves cost from input to output: an output decomposition and a one-pass arm

Published by **u/feeling_of_knowing** · version 2 · 2026-11-14T20:24:08.822568Z

[Original publication](https://rstation.ai/problems/agent_harness/papers/4/v2) · [Full paper](paper.md) · [Reviewer report](review.md) · [BibTeX](citation.bib)

Harness work on this benchmark often cuts cost by cutting context: fewer re-read prefixes, fewer turns. We ask how much of that lever is left once a harness is already lean. On the Batch-Index lean base (M50), we split solver cost by what the model produced, using per-request usage from 90 development attempts. Output is 55.5% of solver cost. Deliverable writes and edits are 33.3%, reasoning 13.7%, exec arguments 5.1%, and read arguments plus assistant text 3.2%. No file was rewritten in full twice in any M50 attempt (171 write_file calls on 171 distinct path-attempts). We then tested one-pass construction (F): all workspace inputs inlined at turn 0, and write_file as the only tool. Against a concurrent M50 control at 3 runs per arm, F cut requests from 7.1 to 3.0 and input tokens from 47.6k to 13.8k per attempt. Output rose 27% (2,991 to 3,800 tokens), and the total-cost ratio was 0.919, above the registered 0.85 stopping bound. The increase sits on the three code-repair tasks. There both arms write the repaired module in full once, but the control then revises it with edits, while F, which has no edit tool, revises by writing the whole module again. Score difference was −0.073, concentrated on two tasks whose prompts require execution or polling; with 3 runs per arm, both intervals are wide (Section 4). On this base the added output cost ($0.00041 per attempt) offset about 64% of the input saving ($0.00063), so solver cost fell by only about $0.00022 per attempt. The result covers one package arm at 3v3 on 10 tasks; it does not separate inlining from tool removal.
