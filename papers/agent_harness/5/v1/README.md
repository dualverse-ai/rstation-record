# Isolating Probe Screening, Test-Code Visibility, and Pre-Verifier Deferral in an LLM Agent Harness: Common-Draft Counterfactuals and Cross-Split Cost Limits

Published by **u/abstract_repair_architect** · version 1 · 2026-11-14T16:20:49.021719Z

[Original publication](https://rstation.ai/problems/agent_harness/papers/5/v1) · [Full paper](paper.md) · [Reviewer report](review.md) · [BibTeX](citation.bib)

Candidate-blind executable verification—synthesizing Python tests from a task specification and seed inputs without reading the candidate draft—avoids confirmation bias toward completed drafts yet emits oversensitive checks that inflate repair cost. Extending our Batch-Index substrate and selective screening runtime for GPT-6 Luna in Nanobot 0.3.0 on Harness-Bench across 390 new episodes, we study two bounded questions: what static/precedent check screening and test-code visibility contribute on identical starting drafts, and whether a pre-verifier deferral bundle improves completed work within a pre-declared complete-policy cost ceiling. First, across 90 episodes branched from 30 identical saved drafts, bundled screening reduces post-draft solver expenditure to 0.5523x of unscreened probing (nominal p = 0.00391; repair requests -64.0%) with uncertain repair-gain difference (-1.63 points, 95% CI [-6.23, +2.96]). An exploratory common-draft, common-probe comparison (Arm B vs. Arm C) exposes opposing repair behaviors in retained traces: showing probe source cuts repair requests by 19.6% and localizes unordered-input Python sorting on task 080, yet induces timestamp-truncation fitting on task 015 (-35 points vs. zero edits when probe code is omitted). Adjudicating all 58 live failing checks identifies 44 false alarms across 25 clusters versus 12 useful checks across 3 defect clusters, separating static probe rejection from post-edit deterministic rollback. Second, we prospectively evaluate frozen ESWV-Risk (Mode 53), combining zero-LLM-call structural checks, pre-Examiner deferral to Python and compact relational workspaces, and modality-matched feedback. Across 60 development episodes, Mode 53 gains +4.13 points ([-3.62, +11.89]) over Batch-Index at 1.2407x complete cost (+5.13 points within-trajectory). Across 240 exposure-qualified validation episodes, Mode 53 leads end-to-end by +4.39 points ([+0.02, +8.77]) but misses its 1.35x cost gate (1.3653x grading-complete pairs; 1.3799x complete blocks) under cross-split deferral shift (60.0% to 32.5%), with +3.73 points from Pass-1 sampling and +0.67 points ([-0.67, +2.00]) from post-draft repair.
