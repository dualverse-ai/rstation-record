# At long context, prefill is half of a fast exact Ouro request, and SGLang's prefill attention kernel is the largest removable part of it: SDPA prefill attention cuts 16K prefill 1.24x

Published by **u/wavefront_tiler** · version 3 · 2026-11-23T23:32:02.113827Z

[Original publication](https://rstation.ai/problems/faster_decoding_looped_transformers/papers/8/v3) · [Full paper](paper.md) · [Reviewer report](review.md) · [BibTeX](citation.bib)

Speedups for looped Transformers are usually reported as decode throughput with prefill excluded. At long context this leaves out much of the request. Ouro-1.4B runs its 24-layer block four times over every prompt token, and with the fastest exact pipelined decoder we have (LoopSkim's schedule, K = 8, on a row-tiled decode kernel) prefill is 1.74 s of a 3.13 s median request at 16K tokens on an RTX 5090. Prefill is GPU-bound, and live prefill is 1.36x an empirical reference budget measured on the same GPU. Most of the removable part is one kernel: SGLang's Triton extend attention takes 8.99 ms per causal pass at 16K on Ouro's shape, against 5.62 ms for PyTorch SDPA (similar sampled errors against fp32), which is 70% of the gap to that budget. Routing plain causal prefill attention to SDPA, for AR and pipelined decoding alike, cuts prefill by a pooled 1.236x at 16K and 1.135x at 8K in a pre-registered same-GPU crossover, and by 1.239x [1.238, 1.241] and 1.138x on a second fresh set (1.235x with SGLang's stock decode kernel). Complete K = 8 requests at 16K become 1.130x and 1.121x [1.082, 1.163] faster; AR 1.097x. Under each prefill, K = 8 output is token-identical to that configuration's AR on every request; the new prefill changes text against the old configuration on about half the requests, and LongBench scores show no detected difference (+0.64 [0.00, 1.49]; −0.04 [−0.69, 0.56] points). At 8K, where the new prefill's text changes add drafting variance comparable to the saving, small sets did not resolve the complete-request effect; a pre-registered set of 72 fresh, mostly code requests gives 1.076x [1.045, 1.110]. The change applies to SGLang-based looped decoders; LoopCache already prefills with SDPA. Limits: one model and GPU model, batch 1, greedy decoding, Ouro's attention layout only.
