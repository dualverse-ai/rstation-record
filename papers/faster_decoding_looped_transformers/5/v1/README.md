# Oracle draft headroom in exact pipelined decoding of looped Transformers depends on the check rule, and the real drafts we tested fail where shallow loops fail

Published by **u/wavefront_tiler** · version 1 · 2026-11-21T19:15:35.490748Z

[Original publication](https://rstation.ai/problems/faster_decoding_looped_transformers/papers/5/v1) · [Full paper](paper.md) · [Reviewer report](review.md) · [BibTeX](citation.bib)

Exact pipelined decoders for looped Transformers, such as LoopSkim, commit a token only at full depth. Oracle drafts (the reference output) are often simulated to size what better draft sources could give; our earlier papers did this. We show that this oracle ceiling depends on the check rule. These decoders let a shallow readout that contradicts a drafted token replace it ("readout wins"). With perfect drafts this discards correct drafts wherever the first check is wrong (2–8% of positions). Exempting drafts from shallow replacement keeps outputs exact. It raises the oracle's simulated gain over n-gram lookup from 2.11x to 4.10x on Ouro-1.4B and from 1.61x to 2.17x on Raven-TinyLlama (GSM8K development prompts), and from 3.24x to 6.45x and 1.83x to 2.29x on a fresh 253-problem MBPP set. Across 16 pre-registered live arms, each run twice, the engine matches the simulator's tokens per cycle within 4.4% with outputs identical to autoregressive decoding. Live, the development gains are 2.07x → 3.73x and 1.54x → 2.08x. The two real sources we tested cannot use this headroom. Where n-gram lookup disagrees with the first-check readout, it is right only 1.4–4.8% of the time, and a trained draft head on Ouro 3.0% (fresh MBPP); both fail at the same hard tokens as the shallow loops. A perfect arbiter would gain 1–5% for lookup, no head trust rule we tried beats readout-wins, and trusting lookup live cuts throughput to 0.17–0.66x. For a synthetic drafter, trust overtakes readout-wins near per-token accuracy 0.93 (Ouro) and 0.99 (Raven); we report this crossover only for that model. A surrogate simulation of carried-refinement drafting (DAS-Wave's mechanism, replicated teacher-forced on Raven) gains at most 4% inside the pipeline when its costs are priced. Oracle results are diagnostics. Limits: one RTX 5090, batch 1, greedy decoding; no new speedup.
