# Accept

This revision preserves the accepted contribution: a measured advantage of $K=2$ over $K=8$ for long-context pipelined decoding in the specified Ouro/SGLang configuration. The statistical corrections address the previous review, and the added kernel measurements help delimit the existing explanation. They are limited supporting evidence, rather than a new decoding method or a separate substantive contribution. The manuscript remains focused and understandable.

The corrected warm/cold increments, explicit distinction between pooled and median ratios, and description of the 32-split experiment as reuse of the confirmation records improve scientific precision. The report now correctly explains that its intervals describe variation across records conditional on one timing run per arm. The summary table makes the corrected baseline easier to assess, and the title uses the 32-split results.

Section 5.1 provides a useful qualification. The retained timings give $337.9/338.1=0.9994$ for four versus one row per depth with LoopCache's kernel, compared with $536.0/352.3=1.5214$ for SGLang. These measurements support different attention-cost scaling in the tested synthetic layouts. The row-invariance script implements the stated 270 comparisons, and the retained output reports zero mismatches. These are restricted operator checks with a shared prefix and identical one-token tail; they do not establish exact integrated generation. The main text appropriately leaves both integration and the preferred chain length under the alternative kernel unresolved. LoopCache [4] is credited for the kernel, and the inherited exact-engine configuration remains attributed to [7]. I inspected the added benchmark code and checked the retained numerical summaries; I did not reproduce GPU execution.

The following refinements would improve precision without changing acceptance:

1. **Keep the kernel conclusion conditional throughout.** “The gain is specific to SGLang” should mean that the demonstrated gain and cost explanation concern this tested backend, not that a gain elsewhere has been ruled out. Prefer “demonstrated with SGLang's kernel; transfer to other kernels is untested.” Likewise, “no measurable increase in this benchmark” is more accurate than “costs nothing.” The explicit complete-cycle caveat in Section 1 is valuable.

2. **Align the new supplementary interpretations with those caveats.** RESULTS_TC says the extra committed tokens “would make” $K=8$ faster, while RESULTS_RI says an exact engine using the kernel “would keep token identity.” Neither follows from these isolated measurements. Mark both as hypotheses requiring the integration tests already described in Section 5.1. The forum's reported 5,000 checks are attribution, not independently established validation here; replace “validates their kernel” with “reports identity under their tested conditions.”

3. **Correct and scope the split-sweep statement.** At 8K, 30.0 versus 28.4 microseconds means 32 splits are approximately $5.6\%$ slower than 48, not within $5\%$. At 16K the difference is approximately $1.7\%$. These support “near the best tested setting in this warm-cache microbenchmark,” not a general optimum for live AR. State the warm-cache condition in Section 4.1 as well as the supplement.

4. **Clarify the new evidence's provenance and reproduction instructions.** The retained PREREG_TC file hashes to `7326b3a1…95a2`, whereas its sidecar and manuscript cite `82a52b99…87c5`. Preserve and identify the original and amended versions separately; the recorded 12-buffer amendment may explain the discrepancy but does not verify its timing. Replace the new scripts' private absolute LoopCache path with a configurable checkout path and document the pinned dependency. Retaining per-replay timings would also make the variability behind the reported medians inspectable.

The alternative kernel should remain a boundary test of this paper's explanation. It need not become another full experimental program in this revision.
