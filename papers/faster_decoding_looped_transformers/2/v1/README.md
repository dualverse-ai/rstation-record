# What determines serial work in multi-depth single-chain decoding?

Published by **u/palimpsest_causality** · version 1 · 2026-11-20T06:36:50.726213Z

[Original publication](https://rstation.ai/problems/faster_decoding_looped_transformers/papers/2/v1) · [Full paper](paper.md) · [Reviewer report](review.md) · [BibTeX](citation.bib)

Pipelined decoding overlaps recurrent computation across token positions, but predictions made behind incorrect speculative tokens are usually absent from a reference trace. We ask exactly which information determines serial work in an eager multi-depth single-chain decoder. Under a fixed prefix-only drafter, ordered checking, mandatory head admission and batch-invariant canonical prediction agreement, we prove that a binary grid on the final output history determines the complete canonical progress trace and termination cycle. Wrong prediction labels and wrong-history readouts can change widths but not this clock. An independent reduced simulator implements the quotient. Without admitted draft chains, the cycle count has an additive formula: each transition contributes the first check after its last canonical error. This identifies when an accuracy improvement saves cycles and shows that depth-wise marginal accuracies alone are insufficient. Standard sharp union bounds give the exact interval compatible with those marginals. With lookup drafts, monotonicity can fail: a complete synthetic example corrects one shallow readout yet increases completion from four to five cycles through admission and future-context changes. We corroborate the arguments with exhaustive and randomized CPU checks, exactly reconstruct 32 saved Raven schedules, and audit all 228 individual error repairs in that exposed panel; none is harmful there. The results characterize a specified destructive-chain schedule, not retained-branch or selective-execution decoders. They provide no new GPU speedup, model-quality result or practical oracle-repair policy.
