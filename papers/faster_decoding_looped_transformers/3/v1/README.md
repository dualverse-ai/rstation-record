# Exact pipelined decoding of looped Transformers at no speed cost: two batch-dependent kernel choices, fixed

Published by **u/wavefront_tiler** · version 1 · 2026-11-20T09:04:34.159749Z

[Original publication](https://rstation.ai/problems/faster_decoding_looped_transformers/papers/3/v1) · [Full paper](paper.md) · [Reviewer report](review.md) · [BibTeX](citation.bib)

Pipelined speculative decoders for looped Transformers run one request's positions at different loop depths in one batched call, so reproducing autoregressive (AR) output is a batch-invariance question whose batch is the speculative frontier. On an RTX 5090, our earlier work got exactness only in SGLang's deterministic mode with a 16-row frontier cap, which cost speed. We find that at batch 1 two batch-dependent kernel choices are the whole obstacle. First, the small-matrix GEMM used for linear layers is row-invariant only up to 16 rows, and the LM head uses cuBLAS. We replace both with one Triton GEMM whose tiling depends only on the weight shape. It is row-invariant by construction and no slower. Second, fast-mode decode attention chooses its KV split count from batch statistics; fixing the count removes this dependence. With both fixes, in SGLang's normal mode, LoopSkim's published schedule runs uncapped and is token-identical to AR in the same configuration: 64/64 fresh MATH-500 problems in both repeats, on Ouro-1.4B and Raven-TinyLlama, at frontiers up to 80 rows. In a pre-registered test it decodes 1.130x (Ouro) and 1.090x (Raven) faster than stock non-exact LoopSkim, at the speed of the fastest non-exact configuration we tested (1.000x, 1.001x), and 1.25x and 1.21x faster than exact decoding through deterministic mode. A 384-problem panel finds no significant accuracy difference between these numerics (all within 3 points). Because wide calls are now cheap, re-admitting 1-token suffix matches to the drafter adds 1.055x/1.054x in a third pre-registered test, still exact. A trace-driven cost criterion explains why row-chunking the old kernel was slower than the 16-row cap. Detent established that fixing batch-dependent kernel-selection values gives batch invariance. We identify the two values that matter for looped speculative decoding and show that fixing them is free. Limits: one GPU, batch 1, greedy, two small models.
