# Accept

This revision preserves the accepted contribution and improves its scope, attribution, and evidence. The MBPP+ evaluation supplies supporting validation on another task type, and the prefill dispatch change corrects a practical limitation of the same implementation. The compiler-specialization checks and replacement of the warm-cache timing table likewise clarify the existing kernel claim. These are appropriate additions to this paper. The resulting manuscript still explains a coherent contribution: removing the numerical obstacles to wide-frontier speculative decoding in the specified backend. A separate submission is unnecessary.

The corrections to the 80-row implementation limit, empirical exactness, Table 3's reference configuration, and quality uncertainty address the earlier review well. Crediting Thinking Machines [16] alongside Detent [10] improves attribution without changing the application-specific novelty. The added prefill explanation is useful: AR and speculative decoding can share the same prompt computation while reserving the invariant implementation for decode-sized calls. The manuscript appropriately discloses that the revised configuration was evaluated again on exposed MBPP+ data and compared with stock runs from an earlier session.

I reproduced the new MBPP+ analysis from the retained records. The reported median decode speedups, end-to-end speedups, bootstrap intervals, correctness counts, and sign tests reproduce. The recorded output hashes agree with the respective AR reference on all 378 problems in both repeats, for both F and F80 on each model. The newly supplied MATH-500 token lists also agree directly between F and its AR reference on 64/64 problems per model in the supplied first repeat; all 512 supplied token lists reproduce their recorded hashes. Earlier per-task measurements and correctness records are preserved. The cold-cache data reproduce the reported Ouro layer-sum ratios of approximately $1.00$–$1.03$, $0.89$, and $0.47$. These checks validate retained evidence and calculations; I did not reproduce GPU generation, GPU timings, or answer grading.

Several minor qualifications would make the revision more precise:

- **Distinguish the two MBPP+ numerical references and their quality evidence.** F80 changes outputs relative to F on 42/378 Ouro problems and 63/378 Raven problems in the first-repeat records. Its exactness is therefore specifically relative to AR-F80. The reported pass@1 counts belong to F/AR-F, and the supplement does not provide F80 grading. State this explicitly so readers do not transfer F's quality results to the recommended F80 configuration. Also replace “pass@1 was unchanged” with “no statistically significant difference was detected”: the displayed counts differ.

- **Keep the timing uncertainty scoped to the measurements.** F80's task-bootstrap intervals do not quantify variation between GPU sessions. The supplement's P43 statement that repeats within each session agree to less than 1% is too broad: the median repeat-1/repeat-2 decode-ms/token ratios are about 1.027 for Ouro's stock LoopSkim arm and 1.021 for its F42 arm. Correct that statement and retain the separate-session qualification. This does not overturn the reported speedups.

- **Align introductory kernel wording with the corrected table.** “Faster above 8 rows” is not true for every projection: Raven QKV is slower at 16 rows. Specify the aggregate comparison and tested widths. Similarly, carry Section 3's compiler qualification into the introductory “row-invariant by construction” wording. The supplied `triton_nospec_check.py` checks the nonspecialized build at every width from 1 to 80, but compares it with the specialized build at seven selected widths; make that distinction explicit or supply the additional specialized-build check claimed in the text.

- **Finish the reproduction-documentation cleanup.** The README still identifies `bench.py` with Table 1, although the replacement table uses `cold_graph.py`. `accept_by_width.py` now references `_paths.OUT` without importing `_paths`. Add explicit MBPP+ preparation and F/F42/F80 configuration examples to `RUN.md`, whose worked preparation command currently covers MATH-500. The private attention-test bundle's hashes identify evidence but do not make it inspectable; describe it as supplementary corroboration unless it becomes available.

These points are bounded reporting and reproducibility corrections. The new evidence supports the existing contribution, and the revision does not materially weaken its central argument or clarity.
