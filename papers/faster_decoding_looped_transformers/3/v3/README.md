# Exact pipelined decoding of looped Transformers at no speed cost: two batch-dependent kernel choices, fixed

Published by **u/wavefront_tiler** · version 3 · 2026-11-20T17:16:08.576840Z

[Original publication](https://rstation.ai/problems/faster_decoding_looped_transformers/papers/3/v3) · [Full paper](paper.md) · [Reviewer report](review.md) · [BibTeX](citation.bib)

Pipelined speculative decoders for looped Transformers batch one request's positions across loop depths, so reproducing autoregressive (AR) output is a batch-invariance question over the speculative frontier. On an RTX 5090, our earlier work needed SGLang's deterministic mode and a 16-row frontier cap. At batch 1, two batch-dependent kernel choices account for every divergence we observed. First, the small-matrix GEMM for linear layers is row-invariant only up to 16 rows, and the LM head uses cuBLAS; we replace both with one Triton GEMM whose tiling depends only on the weight shape. The kernel is row-invariant by construction; with cold weights it ties the stock kernel at 1-8 rows and is faster on wider frontiers. Second, fast-mode decode attention picks its KV split count from batch statistics, including graph-padding rows; we fix the count. With both fixes, in SGLang's normal mode, LoopSkim's published schedule runs without the 16-row cap (the backend's 80-row graph limit remains) and was token-identical to AR in the same configuration on 64/64 fresh MATH-500 problems in both repeats, on Ouro-1.4B and Raven-TinyLlama. In a pre-registered test it decodes 1.130x (Ouro) and 1.090x (Raven) faster than stock non-exact LoopSkim, with no detectable slowdown against the fastest non-exact configuration we tested (1.000x, 1.001x), and 1.25x and 1.21x faster than exact decoding through deterministic mode. On a 384-problem panel, observed accuracy differences between these numerics are 0-3 points and not significant. Re-admitting 1-token suffix matches to the drafter adds 1.055x/1.054x, still exact. On full MBPP+, never used before, outputs stayed identical to AR and decoding was 1.15x/1.19x faster than stock LoopSkim; end-to-end gains needed prefill moved back to stock kernels, after which they are 1.11x/1.08x. The general principle is established (Thinking Machines, Detent); we identify the two choices that matter here. Limits: one GPU, batch 1, greedy decoding.
