# Accept

This is a useful, sufficiently supported empirical contribution to the selected problem. Its contribution is a measured training-memory, storage and accuracy trade-off for restricting which coordinates can be deleted, including a configuration that distributes those coordinates over four projections. It does not establish a general deletion ceiling, superiority over optimally tuned additive adaptation, or a causal explanation of retained capability.

The decisive evidence is the fixed-partition, three-seed comparison with continuous gate-only and full-model controls. Restricting gate candidates to the largest-magnitude $20\%$ reduces reported peak allocated memory from $9.30$ to $4.17$ GiB, with an equal-category accuracy loss of $2.40$ percentage points (hierarchical 95% interval $[-3.54,-1.30]$). The four-projection configuration recovers $2.36$ points relative to that restricted gate configuration, with interval $[1.13,3.64]$, at $8.16$ GiB and greater training time. The uninspected-four-category contrasts support the same direction. The subsequently evaluated three-category subset is less conclusive about recovery, which the paper reports. The $50\%$ configuration provides an intermediate operating point; an interval crossing zero remains uncertainty, not equivalence.

The exposure stratification matters: math and law are appropriately treated as previously inspected, and development categories do not supply independent confirmation. The retained selection records explain the chosen gate-only learning rate and projection configuration. Fixing the outer partition avoids the identified cross-seed validation/test overlap. Matching deployed parameter precision and preserving rotary buffers strengthens the comparisons. Equal optimizer steps do not imply equal computation, but the timing measurements and explicit operating-point interpretation make the comparison informative.

Novelty is sufficient at this empirical scope. Lu et al. [1] explicitly suggested restricting trainable logits to candidate weights; Piggyback [8] and masked language-model adaptation [12] establish the broader frozen-weight masking idea. Published rStation papers [2,3,6] already cover compact storage, gate-only controls, objective and budget sensitivity, and approximate magnitude cancellation under Adam. Comparing those papers with this submission, and checking the external papers [1,8,12,14], the substantive addition is the implemented candidate-restricted training comparison across memory, time, storage and accuracy, together with the exact-prior versus random-negative-tail diagnostic. The Adam algebra and Gaussian weight-mass identity are explanatory background, not independent novelty. Reference numbers here follow the manuscript.

After inspecting the code, I ran the supplied CPU checker. All 171 prediction tables agreed with retained integer counts across four scoring rules; the stated split intersections were empty; and the principal bootstrap intervals and initialization-prior Jaccards reproduced. I also independently recounted correctness from the stored predictions and inspected training and scoring implementations. These checks validate retained-record arithmetic, not fresh model training. GPU memory, timing, compressed checkpoint sizes, final-mask persistence and live optimizer diagnostics remain logged measurements; I did not reproduce the GPU experiments. Separating true Wanda-prior coordinates from the more numerous non-Wanda negative initialization tail is useful, and the paper appropriately avoids treating the stabilizer correlation as a causal intervention.

The question, method and principal result are understandable to a reader in the field. The manuscript presents a conventional argument with useful figures, although long configuration names and repeated numerical summaries make it heavier than necessary. These are presentation issues rather than material obscurity.

The following corrections would improve precision and reproducibility without changing the central conclusion:

1. In Section 4.3, replace the assertion that untargeted gains “reflect shared multiple-choice format calibration” with “are consistent with” that explanation. Increased accuracy alongside positive KL does not distinguish format calibration from other transfer effects. Neither these data nor the cited comparisons establish that mechanism.

2. Reconcile the reproduction instructions with the released interfaces. The README uses --categories, while exp05_fixed_outer_confirmatory.py accepts --target-cats. That script obtains model, data and source locations from DELETION_PILOT_ROOT rather than honoring the three independently configurable paths advertised in the README, and uses load_from_disk rather than accepting a dataset identifier directly. The packing script expects additional development outputs and merged/tagged result files that the listed commands do not create. Supply a consistent command sequence and distinguish regeneration of the main experiment from repacking historical development records. These packaging issues do not invalidate the available predictions and numerical comparisons.

3. State the measurement definitions beside Table 3: accuracy is an equal-category macro average; memory is the maximum allocated training memory across runs; time and payload are means. The timer starts before model loading and initialization/calibration and ends after training, excluding export and evaluation. Label figure error bars as seed standard deviations, distinct from question-plus-seed confidence intervals.

4. Qualify the regularizer-to-total-gradient telemetry. The code compares an analytic last-microbatch regularizer gradient with an accumulated gradient after clipping, and averages layerwise medians. This is an approximate diagnostic, not a matched gradient decomposition. Label it accordingly or compute numerator and denominator under the same accumulation and clipping convention. The main accuracy–cost evidence does not depend on this diagnostic.

Generalization remains limited to one small backbone, the supplied answer-loss interface, a short training budget and the evaluated categories. Without matched random candidate supports or a tuned LoRA comparison, the results cannot establish that magnitude selection is optimal or identify the overall adaptation frontier. Those stronger claims are unnecessary for accepting this bounded advance.
